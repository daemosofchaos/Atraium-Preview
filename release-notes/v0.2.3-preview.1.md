# Atraium 0.2.3 Preview 1

Atraium 0.2.3 Preview 1 adds reusable model profiles, more flexible tool access, and improved coding and Workspace workflows.

## Highlights

### Reusable model profiles

Configure a provider and model once, then reuse that profile across Atraium. Profiles can be assigned to the main assistant or to supported specialist capabilities such as embeddings, image generation, realtime interaction, speech output, and transcription.

Rooms and Workspaces can select their own model profile while retaining the assistant identity, instructions, tools, tasks, notes, and files.

### More flexible model controls

- Improved support for compatible reasoning models and provider-specific settings.
- Optional sampling controls for models that do not accept them.
- Better guided configuration and model-profile management.
- Support for compatible local and self-hosted OpenAI-style endpoints.

### Room and Workspace tool access

Tool access can be configured separately for a Room and refined for a Workspace. Frequently used tools can be prioritised while broader capabilities remain available through Atraium's searchable catalog.

The assistant may propose additional tool access, but the user remains responsible for approving or dismissing that request.

### Improved coding workflows

A focused coding toolset makes it easier for compatible models to inspect projects, read and edit files, search content, apply patches, and run commands. Existing specialist development and document tools remain available when enabled.

### Workspace improvements

- Faster browsing and filtering of large tool catalogs.
- Improved task and note actions.
- More reliable Workspace updates during active assistant work.
- Navigation, settings, and mobile-layout refinements.
- An optional compatibility setting for models that require the system instruction to remain first.

## Platforms

- **Windows desktop:** recommended preview experience.
- **Android and Web:** not included in this release.

## Important notes

- This is preview software and may contain breaking issues.
- Model and tool support varies by provider, endpoint, and selected model.
- Tool access should be limited to what a Room or Workspace genuinely needs.
- Provider-side usage, billing, and policy controls remain authoritative.
- Support is best-effort.
