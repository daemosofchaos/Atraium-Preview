# Atraium 0.4.2 Preview 1

Atraium 0.4.2 Preview 1 makes Workspace content easier to retrieve and save, and fixes direct-tool defaults in new Rooms and Workspaces. It follows [0.4.1 Preview 1](https://github.com/daemosofchaos/Atraium-Preview/releases/tag/v0.4.1-preview.1).

## What changed

### Retrieve the record you need

- Assistants can now retrieve an individual Workspace note or task by its ID, including its full content and metadata, without listing the entire collection first.
- A lightweight artifact index helps assistants find generated documents by name or keyword without loading their file contents. New retrieval and export capabilities are also easier to find through the tool gateway when routed there.

### Save messages and artifacts to files

- Assistants can export one or more complete user or assistant message bodies to local files. Markdown (`.md`) is the default, with custom filenames and extensions supported.
- Export messages separately or combine them into one file in the requested order. Original text, Unicode, whitespace, code fences, and line endings are preserved rather than regenerated or summarized.
- Assistants can save generated documents, images, and chat attachments in batches, copying their original bytes and preserving their format. Files generated earlier in the current response can be saved without waiting for the response to finish.
- Exports use existing file permissions and do not overwrite files by default. Source and destination validation, size limits, background processing, and cancellation cleanup help avoid truncated exports and half-written destination files.

### Direct tools stay direct

- Fixed inherited tool routes displaying as **Gateway** in **Tools & access** when the runtime treated them as **Direct**. The settings surface, runtime, and direct-access requests now share the same default-route rules.
- **Workspace, Local Computer, Turn Context, Attachments, and Widgets** remain Direct by default, including in newly created Rooms and Workspaces.
- These built-in families no longer displace each other under a former shared 24-tool limit. Up to **24 additional explicitly direct-routed catalog tools** can be exposed alongside them; additional overflow remains gateway-accessible.
- Explicit **Gateway** and **Disabled** choices remain respected. Existing saved policies are preserved, and inherited contexts need no reset or manual initialization.

## Platforms

- **Windows desktop:** recommended preview experience.
- **Android:** early sideloaded preview for Android 7.0 or later, supporting arm64-v8a devices and x86_64 emulators.
- **Web, macOS, and iOS:** not included in this preview.

## Important notes

- This is preview software; support is best-effort. Model and provider capabilities vary.
- Message exports contain message bodies, not reasoning, tool logs, attachment bytes, or rendered widgets. Changing an extension does not convert the content. Use **Save PNG** for inline widget visuals.
- Retrieval and exports stay within the selected Workspace and active Room. Saving requires an allowed destination; no file access is granted automatically. Mobile destinations depend on permitted app storage.
- More built-in tools are now exposed directly, which can increase tool-schema input and provider token usage. Route unwanted families through the gateway or disable them in **Tools & access**.

Atraium does not include provider credentials, model credits, or token allowances. You are responsible for configured provider and service charges. Multiple assistants can incur costs simultaneously. Set provider-side limits and review [Token usage and provider billing](https://github.com/daemosofchaos/Atraium-Preview/blob/main/TOKEN-USAGE-AND-BILLING.md).
